# Программный контракт сигналов WB8.5 — черновая основа v0.1

## Локальные поля 0.10 — 15.11.2026

Новых физических входов не добавлено. Различаются новый нормализованный cooling.required и исторический lastKnownRequest; старый запрос/DI после reboot не являются доказательством текущего разрешения. Добавлены отдельное подтверждение закрытия для охлаждения D-164, предупреждение повторов/число событий и признак принятого начального OFF при согласованных 111/000. Поля — в [INTEGRATION_INTERFACE](../INTEGRATION_INTERFACE.md), [границы](2026-11-15_Симулятор_восстановления_при_охлаждении.md). Карта регистров, свежесть физических каналов и WB 8.5 не подтверждены.


## Локальные поля 0.9 — 15.11.2026

Добавлены `shod.feedback` (исходные В 0–10 с независимыми качеством/свежестью) и выход `shod.voltage` (0/5/10 В). K=1,2, доступный диапазон 0,5–2, корректирует только обратную связь; 120% не превращается в 100% для диагностики. Прежние vfd.running/frequency/exchange/fault и cooling.required используются без новых физических адресов. Последний — испытательный логический запрос, не измеренная температура. `fanTestRate` 0,5 Гц/с (0,1–5), границы Fmin/Fmax по D-276. Внутренняя резервная частота ПЧ проверяется лишь явно заданной предпосылкой, не записывается автоматически.

Команды/снимки/телеметрия описаны в [INTEGRATION_INTERFACE](../INTEGRATION_INTERFACE.md), ограничения — в [отчёте](2026-11-15_Симулятор_охлаждения_ШОД_дымососа.md). Конкретные признаки недостоверности частоты, физические каналы и совместимость WB 8.5 этим не подтверждены.


## Дополнение локальной 0.8 — 15.11.2026

Новых физических входов нет: используются прежние `st.open/st.closed`, фазные входы, подтверждения ПЧ и нормализованные условия. Добавлены запросы HMI проверки/возврата питания ШТ, настройка `stReleaseSeconds` и переходы общего цикла; их точные условные поля — в [INTEGRATION_INTERFACE](../INTEGRATION_INTERFACE.md). [Охват](2026-11-15_Симулятор_проверок_ШТ.md). Реальные регистры/драйверы/NV не назначены.

## Локальные поля 0.7 — 15.11.2026

Физические сигналы/адреса не добавлены. Давления — прежние независимые данные после фильтра; `pressure.lowTrip` отличается от `lowAlarm/highAlarm`, блокировка завершённого останова отдельная. `boot.phase/reasons/storage` и флаги продолжения описывают восстановление из памяти имитатора. Старые DI/выходные команды после reboot не являются новыми подтверждениями. Локальные HMI-команды `reset_pressure_stop`, `continue_stop_after_restart` сохраняют проверку поколения/контекста. [Контракт обмена](../INTEGRATION_INTERFACE.md), [точный охват 0.7](2026-11-15_Симулятор_давления_и_перезагрузки.md). `MEMORY_SIMULATION_ONLY` не означает NV/WB-совместимость.

## Локальные дополнения 0.6 — 15.11.2026

Физических входов/выходов и их адресов не добавлено. `recovery_fixture` задаёт синтетический контекст допуска, отдельно от обычного Пуска. `engineering_test(kind=branch)` и `reset_pump_group` — локальные действия с поколением/контекстом; `recovery.active/history` и `pumpGroup.groupReturns` — состояние модели. Результаты объединённого теста раздельные для насоса/затвора, успешные измерения не равны разрешению возврата. Ручные задания `remaining=null` не имеют назначенного таймаута. Узкий согласованный D-177 отражается отдельной причиной и состоянием STOPPING в прежнем обмене. [Полные границы](2026-11-15_Симулятор_восстановления_и_объединённой_проверки.md), [контракт обмена](../INTEGRATION_INTERFACE.md). WB 8.5 остаётся непроверенным.

## Локальные дополнения 0.5 — 15.11.2026

[Охват/ограничения](2026-11-15_Симулятор_затворов_и_возврата.md), [межсистемная граница](../INTEGRATION_INTERFACE.md). Физическая карта не изменена.

| Условное имя / команда | Смысл и граница |
| --- | --- |
| `engineering_enter(true)`, `engineering_leave()` | Явная тестовая предпосылка выключенной печи/действия инженера, отдельный сеанс. Не аппаратный DI и не реализация пароля. |
| `engineering_test({kind,pump,repaired})`, `engineering_stop()` | `kind=valve/pump`, `pump=1/2`; подтверждение ремонта при необходимости, отдельная попытка с блокировкой параллельного теста группы. |
| `engineering_return({kind,pump})` | Отдельный возврат только проверенного механизма/его причин; не пуск и не универсальный сброс. |
| `engineering_isolate/confirm_isolation/confirm_return(1|2)` | Нижний ручной кран конкретной ветви, независимые задание/закрытие/возврат; DI электрозатвора не меняются. |
| `engineering_breaker_off(1|2)` | Отметка ручного отключения автомата привода после проверки на месте, без доказательства электрического напряжения. |
| `engineering_reset_voltage(1|2)`, `reset_flow_faults(true)` | Раздельные сбросы D-143/D-167 с собственными условиями; индивидуальные ошибки/требование полного следующего пуска сохраняются в своей области. |
| `confirm_valve_open(1|2)` | Ограниченное подтверждение D-139/D-172 в текущем разрешённом сценарии, отдельно от DI. |
| `valves.waits/recoveries` | Одна попытка закрытия/ручное ожидание, цель/остаток. После моделируемого reboot остаток приостановлен до восстановления этапа, новые 60 с не назначаются. |
| `pumpGroup.branches[i].manualOpen/manualClosed/valvePumpOff` | Ручное положение и запрет ON по неожиданному закрытию раздельно от электрической ошибки/физических DI. |
| `engineering.enabled/active/results` | Сеанс/попытка, результат `PASSED/FAILED/NOT_CHECKED` и отдельный `valid` для возврата. Исторический успех не равно действующему разрешению. |

Телеметрия в инженерном режиме: основное состояние STOPPED, готовность false, причина «Инженерный режим» (D-254/D-301). Новых основных состояний, Modbus-регистров, оборудования и реальных команд ARANGA/котельной нет. Потеря HMI прерывает проверочные команды по утверждённым 5 с, без автопродолжения. Остальная технологическая загрузка/поведение выходов при реальном reboot не объявлены реализованными.

## Реализация гидравлических полей в 0.4

`flow_control(boolean)` — условное изменение инженерного флага, с имитированными правами в локальной HMI; `flowControl` — сохранённое значение флага в модели. `hydraulicWarning` и критерий отличают ожидание/предупреждение от аварии. `requireFullHydraulicStartup` — требование D-167; `branches[].exclusions` — исключение для проверки, не индивидуальный физический диагноз. [Отчёт](2026-11-15_Симулятор_гидравлической_диагностики.md). Физических адресов и новой электрической схемы нет; производственные права/NV не проверены.

## Реализация части контракта в 0.3

Условные команды HMI `switch_pump(1|2)`, `confirm_valve_closed(1|2)`, `confirm_pump_breaker_off(1|2)` и состояния `pumpGroup` реализованы в локальной модели. [Точные значения, источники и границы](2026-11-14_Симулятор_насосов.md). Это реализация уже согласованных функций, без назначения физического канала или сетевого адреса. Подтверждение оператора не изменяет DI, исключение не означает доказанную поломку конкретного компонента.

Статус: пользователь принял как **черновую основу разработки симулятора**, а не как готовую монтажную карту или проверенный интерфейс оборудования. D-336–D-338. Физические каналы, полярности, адреса и Modbus-регистры не назначены. Реальные механизмы не подключаются.

## Допущение об электрическом согласовании — D-336

Для программы и имитатора все входы и выходы считаются электрически согласуемыми с WB8.5, модулями и исполнительными механизмами. Необходимые промежуточные реле/преобразователи выбираются при проектировании шкафа. Это **не утверждение**, что электрическая схема, подключения, защита и поведение выходов уже проверены.

Общая пометка всех физических строк: **«Проверить электрическую реализацию при проектировании шкафа»**. Конкретные устройства и номиналы без данных не добавляются. Аппаратная защита и реальные состояния при отказе обязательны до подключения оборудования.

## Общие типы и качество

Имена и структуры — программное предложение. `i` означает два отдельных экземпляра 1/2, `phase` — отдельные L1/L2/L3. `bool` имеет значения true/false; отсутствие значения обозначается null отдельно от false. Числа конечные; NaN/Infinity не являются измерениями.

| Поле | Тип и назначение | Источник → получатель |
| --- | --- | --- |
| value | Значение сигнала или null | Адаптер/имитатор → ядро, защита, HMI |
| quality | GOOD / BAD / UNKNOWN, качество последнего ответа | Адаптер/имитатор → потребители |
| fresh | true / false / unknown, актуальность по правилам источника | Адаптер/контроль времени → потребители |
| updated_at | Время последнего ответа именно данного канала | Адаптер → диагностика |
| last_good_value / last_good_at | Последнее достоверное значение и его время | Хранилище измерений → алгоритм разрешённого удержания |
| held | Используется последнее достоверное значение в разрешённой области | Алгоритм → HMI/учёт |
| reason | Причина отсутствия/недостоверности, если известна | Адаптер/ядро → HMI |

В прототипе используются camelCase (`updatedAt`, `lastGoodAt` и т.п.). Внутренний номер ответа различает порядок событий с одинаковым модельным временем. Это не внешний регистр и не дополнительный watchdog ARANGA.

Новый правильный ответ с прежним числом обновляет актуальность. Успех одной операции не обновляет все измерения устройства. Отсутствие данных не заменяется нулём, закрытием или остановом. Если срок устаревания не согласован, новый TTL не назначается: в имитаторе актуальность задаётся явно. У прямых AI согласован фильтр 2 с; v0.1 принимает входы уже после него, физический фильтр ещё не моделируется.

Команда содержит источник, действие, параметры, контекст процедуры, идентификатор и результат приёма. Запрос, итоговая команда, доставка и физическое подтверждение — разные сущности. Успешная запись не доказывает выполнение. Подтверждение старой выдачи не относится к новой. Доступ к итоговой выдаче имеет только защита, D-323.

## Физические входы

Источник — соответствующий полевой прибор; в симуляторе его заменяет явно обозначенный имитатор. Получатели — ядро/защита/HMI. Все строки имеют общие поля качества выше.

| Условное имя | Назначение / тип / единицы / значения | Неизвестность и согласованная реакция |
| --- | --- | --- |
| di.pump[i].phase[phase] | Шесть раздельных фазных подтверждений после контакторов; bool | Неизвестные не равны 000. Напряжение не доказывает вращение; D-142/D-144 в применимой к WB части |
| di.valve[i].open / closed | Четыре концевика насосных затворов; bool | 0/0 не подтверждает крайнее положение, 1/1 противоречиво. Недоступность при снятом питании — рабочее допущение D-258 |
| di.st.open / closed | Два внешних концевика ШТ; bool | Команда и операторское подтверждение не переписывают DI; D-072–D-076, D-162–D-164 |
| di.grid.novatek_ok | Подтверждённая норма сети; bool | false не различает обрыв/сеть/отказ реле; совместная оценка с WB-MAP3EV |
| di.emergency_button | Логическое нажатие кнопки; bool | Полярность не назначена; новая реакция на недоступность входа не придумана |
| ai.pressure.before / after | Давление до/после НГ; число 0–4 бар | 0 бар — допустимое измерение. Один недостоверный: нет ΔP, абсолютный контроль по оставшемуся. Оба: отключение насосов и защитная процедура D-148/D-149 |
| ai.temperature.supply | Основная температура подачи до потребителей; °C | Резерв TUF для расчёта по D-152; защита по принятому набору достоверных температур |
| ai.temperature.return | Обратка после НГ на входе ТО; °C | Нет достоверной температуры — нет достоверного ΔT/тепловой мощности |
| ai.temperature.gas_after_st | Газы после ШТ до ШОД; °C | Нет данных; отдельную неописанную защитную реакцию не добавлять |
| ai.temperature.fan_inlet | Перед дымососом после подсоса; °C | Реакции D-021 с сохранением старших приоритетов |
| ai.temperature.turn_chamber | Камера переворота, термопара K; °C | Диапазон фактического канала сверить; неописанная реакция на отказ открыта |
| ai.sod.feedback_voltage | Обратная связь ШОД; номинально 0–10 В | Полное открытие может быть около 7 В; применяется K. Не считать 7 В автоматически недоходом |

Пределы температурных каналов без паспортной настройки не назначаются. Предварительный бюджет: 14 DI, 8 AI; резервная температура TUF не является дополнительным физическим AI.

## Итоговые команды механизмам

Источник всех `out.*` — защита после рассмотрения запросов основной программы/оператора. Получатель — виртуальный транспорт, позже проверенный физический адаптер. Неизвестные выходы при отказе служб — O14-02; общего OFF или удержания не назначено.

| Имя | Тип / допустимые значения / получатель | Независимое подтверждение |
| --- | --- | --- |
| out.pump[i].run | bool → контактор | Три фазных входа; гидравлика отдельно |
| out.valve[i].direction | STOP / OPEN / CLOSE → две взаимоисключающие команды привода | Два концевика, 45 с; повтор команды не продлевает таймер |
| out.st.direction | STOP / OPEN / CLOSE → ШТ | Концевики, таймеры D-072–D-074 |
| out.st.power_enable | bool → разрешение питания ШТ | true разрешает питание; дополнительный DI реле не назначен |
| out.sod.position_pct | 0–100 % → AO привода | Скорректированная обратная связь отдельно |
| out.vfd.enable | bool → проводное разрешение | Не подтверждение Работа/останова |
| out.heat_removal | bool → местный усиленный теплоотвод | Отдельная обратная связь не назначена |
| out.alarm.light / sound | bool → извещатели | Отдельная обратная связь не назначена; критический звук по правилам D-022 |
| out.vfd.run_command | START / STOP → ПЧ по сети | Ответ записи и отдельный свежий статус Работа |
| out.vfd.frequency_hz | Конечное число, Гц → ПЧ | Фактическая выходная частота отдельно; STOP не превращается в Fmin |
| out.vfd.reset | Однократное событие → ПЧ | Ответ записи и последующая диагностика, по допускам D-052 |

`delivery.status`: UNKNOWN/PENDING/ACCEPTED/ERROR, идентификатор выдачи и время. `execution.confirmed` вычисляется по предусмотренной обратной связи; для механизмов без неё не ставится автоматически. Предварительный физический бюджет 13 DO + 1 AO сохраняется.

TUF: независимая актуальность 5 с и диагностическая выдержка 5 с на канал. Повтор ошибки не перезапускает таймер; первый истёкший срок прекращает удержание. Без прежнего достоверного значения сразу «Нет данных». Удержание для текущих алгоритмов не разрешает начисление энергии: D-155/D-156 исключают диагностические интервалы и весь неподтверждённый интервал после последнего достоверного ответа при истечении актуальности.

## ARANGA — сетевой контракт без назначения регистров

ARANGA — клиент Modbus TCP, сторона ТО — сервер. В v0.1 реального Modbus нет; реализована только независимость ручного режима от синтетического признака обмена. Следующие правила сохранены для последующего сквозного сценария.

| Имя | Тип/направление/назначение | Правило |
| --- | --- | --- |
| aranga.start | bool, ARANGA → ТО | Фронт 0→1; после загрузки/потери обмена сначала 0; недопущенные запросы без очереди |
| aranga.stop | bool, ARANGA → ТО | Уровень 1 выше Пуска, повтор не сбрасывает процедуру; 0 не отменяет принятый останов |
| aranga.frequency_hz | Конечное число, Гц, ARANGA → ТО | LIMIT, затем резонансная коррекция; выход за рабочие границы сам не ошибка данных |
| aranga.frequency_written | Внутреннее событие новой принятой записи | Даже повтор прежнего числа — новая запись, не чтение старого регистра |
| aranga.operation_ok | Успешная прикладная операция именно ARANGA | Чужой клиент/TCP без операции не засчитываются, D-294/D-300 |
| aranga.connected | Производный признак → HMI | 5 с без операций; отдельного таймера записей частоты нет |
| telemetry.state / mode | Четыре состояния / MANUAL–ARANGA, ТО → ARANGA | Аварии и инженерный режим отдельно, состояние не подменяется режимом |
| telemetry.ready / not_ready_reasons | bool / набор причин | Готовность к дистанционному пуску, по действующим разрешениям |
| telemetry.alarms | Набор причин и критичностей | Числовые коды и упаковка не назначены |
| telemetry.bypass_request | bool → ARANGA | Не команда приводу ручного ШБ и не подтверждение открытия |
| telemetry.frequency_target_hz / actual_hz | Числа, Гц | Итоговое задание отдельно от факта; факт со своим качеством |
| telemetry.limit_active / resonance_active | bool | Признаки выполненной коррекции |

Целевые операции 500 мс в согласованной области; это не период всех физических шин. Правила последней сессии:

1. Ручной режим полностью независим от присутствия/утраты ARANGA; только индикация, D-328.
2. Уже В работе, ARANGA: 5 с без обмена → предупреждение, удержание действующего задания, местная корректировка через доступную HMI; без останова/аварийных 38 Гц, D-330.
3. Возобновилось чтение → признак связи восстановлен, частота остаётся действующей. Только первая новая принятая запись возвращает управление ARANGA, D-331. Другие приоритеты и обязательный останов сохраняются.
4. Незавершённый сквозной запуск: D-259/D-260/D-287/D-294 продолжают действовать; рабочее удержание туда не переносится.
5. Новый успешный запуск: Fmin до первой записи после завершения запуска; старое число не считается новым заданием, D-295.

## Привязка части контракта к локальной версии 0.2

Условные операции `ArangaExchange.receive`: `read`, `controls {start: bool, stop: bool}`, `frequency {value: number}`, `failed`. Реальных адресов/регистров это не задаёт. `lastAttemptAt` и `lastSuccessAt` различаются; у частоты — `frequencyUpdatedAt`, `frequencyGoodAt`, `frequencyQuality` и последнее достоверное `frequencyValue`. Порядковый номер записи различает события при одинаковом числе/времени, но не вводит сетевого счётчика или нового таймера.

`aranga.holding/source/activeFrequency` описывают удержание и источник задания отдельно от доступности связи. `telemetry` содержит реализованную часть D-301: основные состояние/режим, готовность/причины/аварии, итоговую и фактическую частоты с качеством, LIMIT/резонанс. Остальные строки контракта не объявляются реализованными. Отдельные команды HMI `mode/frequency` проверяют действующий режим; приём частоты ARANGA в ручной работе не меняет источник.

[Реализованные правила и открытые границы](2026-11-14_Симулятор_ARANGA.md). Качество некорректного payload условного API не назначает код ошибки реального Modbus-устройства. Реакции на аппаратные ошибки и электрические подключения по-прежнему требуют проверки.

## HMI — запросы, не выходы

Источник — управляющий клиент; получатель — обработчик команд, ядро/защита. Каждое действие проверяет права, текущий контекст и разрешения при исполнении. В v0.1 нет производственной авторизации; только один локальный испытатель.

| Имя | Тип/параметры | Ограничения |
| --- | --- | --- |
| hmi.start / stop | Однократные события | Ручной Пуск; принятый Стоп обязателен |
| hmi.set_mode | MANUAL/ARANGA | Ручной → ARANGA только после полного останова; обратный переход D-267 |
| hmi.set_frequency | Конечное число, Гц | Прямое ручное задание через ограничения; D-330 местная корректировка отдельно |
| hmi.set_sod_mode / position | Авто/ручной, число 0–100 % | Старшие защиты сохраняются |
| hmi.select_pump / change_pump | 1/2 | Выбор и запрос смены — разные действия |
| hmi.confirm | Вид подтверждения + текущая процедура | Раздельно ШБ открыт/закрыт, ручные положения, снятие питания/изоляция |
| hmi.revoke_valve_open_confirmation | 1/2 | Без движения и сброса неисправности |
| hmi.engineering_action | Цель, начать/продолжить/отменить/пропустить/повторить | Только предусмотренные допуски; пропуск не успех |
| hmi.return_branch | 1/2 | Отдельный возврат после необходимых тестов |
| hmi.restore_st_power | Подтверждённый запрос | По принятой процедуре, не обход блокировки |
| hmi.reset_vfd / reset_fault | Отдельный запрос/конкретная причина | Не универсальное снятие всех блокировок |
| hmi.reset_runtime | ТО / насос 1 / насос 2 | Три раздельных подтверждения, D-134 |
| hmi.reset_thermal_totals | Подтверждённое событие | Инженер, ТО остановлен; не сбрасывает наработки/сеансы |
| hmi.configure | Параметр + значение | Только утверждённые диапазоны и права |
| hmi.sound_control | Разрешённое действие | Не снимает аварию, не отключает обязательный критический звук |
| hmi.client_exchange_ok / available | Событие клиента / производный bool | Один управляющий интерфейс достаточен; 5 с нет всех → реакции D-332 по состоянию |

После восстановления HMI актуальное состояние без повторения старых нажатий. Пуск при недоступной HMI запрещён, запуск прерывается D-273/D-287, обычная работа продолжает задание с защитами, обязательный останов не отменяется, инженерный тест прекращается по своей процедуре. СП315 опциональна, не условие первой версии.

## Внутренние переменные и настройки

Источник — ядро/защита/хранение; получатели — процедуры, HMI и разрешённая телеметрия. Качество производных зависит от исходных данных и известности сохранённого состояния.

| Группа имён | Тип/единицы/назначение | Правило |
| --- | --- | --- |
| state.main / mode | Четыре состояния / два режима | Неизвестность загрузки отдельно, не фиктивный STOPPED |
| state.frequency_owner / target_hz | Источник задания / Гц | Запуск, ручной, ARANGA, местная коррекция, останов, охлаждение, тест различаются |
| state.stop_required / reason / stage | bool / причина / этап | Связь вернулась — принятый останов остаётся |
| state.start_ready / block_reasons | bool / набор причин | Только актуальные разрешения |
| hydraulics.delta_pressure_bar | P_after − P_before, бар | Оба давления достоверны |
| hydraulics.passage[i] / circulation | Подтверждение с источником / результат и критерий | Открытие не доказывает Q; критерии разных процедур не объединять в универсальный OR |
| pump[i].electrical_state / excluded / faults | Статусы, bool, набор | Общая неисправность измерения не равна отказу обеих ветвей |

| sod.position_pct | Число, % после K | Проверочный допуск ±10 п.п. после K; непроверенную обработку выхода за диапазон не маскировать |
| vfd.stop_confirmed | bool | Свежая обратная связь после подтверждённой STOP, не только частота 0 |
| cooling.requested / permitted / block_reasons | bool / bool / набор | Запрос не равно разрешению; внешнее задание ARANGA не требуется |
| engineering.active / target / stage / result | bool / цель / этап / результат | Не проверено/успешно/неуспешно; успех сам не возвращает механизм |
| supervision.*_cycle | Завершённые циклы основной программы, надзора и защиты | Отдельные 2 с; живой процесс не доказательство завершённого цикла |
| control_fault / control_start_block | Авария / блокировка | NV и отдельный инженерный сброс |
| runtime.hx / pump[i] | Наработки, внутренне с, отображение ч | ТО от принятого Пуска до принятого останова; насосы по итоговым ON, одновременно независимо |

| thermal.power_kw / energy_kwh / mean_kw / window_mean_kw | Числа со знаком | Сеанс только В работе, средние по достоверному времени, окно 5 минут |

Fmin/Fmax исходно 20/50 Гц; настройка 10–100 Гц кратно 5, допустимость пары обязательна. Охлаждение исходно 25 Гц. Резонанс: границы по наладке либо подтверждённое отсутствие; гистерезис 1 Гц, настройка 0,1–5 с шагом 0,1 Гц. Встроенный пропуск ПЧ отключён по инженерному подтверждению; инженерный тест обход не выполняет. Qmin=5 м³/ч (1–42), ΔPmin=0,3 бар (0,1–2); эталонная пара общая обеим ветвям, значения не назначены расчётным примером. K обратной связи ШОД настраивается до теста; числового значения нет. Рампа теста 0,1–5 Гц/с не ограничивает обычное ручное задание.

## Соответствие сокращённым именам первой реализации

В `simulator/src/signals.mjs` перечислены только реализованные входы, остальные строки контракта не объявляются реализованными. Переименование не назначает физический канал.

- `di.st.*` → `st.*`; `di.valve[i].*` → `valve1/2.*`; фазные входы → `pump1/2.l1/l2/l3`.
- Давления → `pressure.before/after`; `tuf.flow_m3h` → `flow`; кнопка → `emergency`.
- `vfd.running`, `vfd.frequency`, `vfd.fault`, `vfd.exchange` — нормализованные модельные данные.
- Выходы: `pump1/2.run`, `valve1/2.direction`, `st.direction`, `st.power`, `vfd.enable/run/frequency`.
- `grid.normal`, `temperature.normal`, `cooling.required`, `configuration.ready` — **агрегированные тестовые предпосылки**, не придуманные физические датчики или новые условия проекта. Их полные расчёты пока не реализованы.
- Профиль v0.1: ручной режим, ветвь 1, холодный ТО без запроса охлаждения, нормальная сеть/температуры, заранее проверенная конфигурация. Загрузка профиля сбрасывает тестовый мир, не является способом восстановления реального ТО.
