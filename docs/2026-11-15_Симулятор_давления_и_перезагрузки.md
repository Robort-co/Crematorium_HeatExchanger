## Что реализовано после 0.6

| Область | Реализация и практические границы |
| --- | --- |
| `PressureProtection` | Разделены немедленный trip, текущая сигнализация низкого/высокого давления, потребность в обоих каналах, незавершённый защитный останов и блокировка нового Пуска после его завершения. Команд выходам модуль не выдаёт. |
| Пороги/гистерезис | P<0,8 — немедленно OFF насосов; OPEN затворам при действующих запретах. Низкая сигнализация после непрерывных 3 с; снятие при норме доступных каналов ≥1,0. Высокая сигнализация после 3 с при P>2,8, снятие ≤2,6, без выключения насоса по этой причине. Входы уже после физической фильтрации; дополнительной задержки trip не добавлено. |
| Качество | UNKNOWN не равен нулю. 0 бар — достоверное низкое давление; >4 бар уже исключается существующим контрактом входа. При обоих недостоверных сохраняются прежние активные тревоги; один нормальный канал возвращает абсолютный контроль, но не разрешает восстановление насосов после потери обоих. |
| Ранний D-149 | До подтверждения ШБ, без командного/другого обязательного останова, после нормализации обоих каналов с гистерезисом и проверки разрешений: STARTING → закрытие обоих затворов → насос/OPEN/+5 с/гидравлика. При отказе закрытия — D-112/D-171. Прежняя прерванная смена насосов автоматически не продолжается. Если давление прервало начальное открытие ШТ, оно завершается до подготовки насосов; подтверждения ПЧ и ШБ закрыт не обходятся. |
| Независимые причины | Стоп HMI/ARANGA, другая обязательная причина, подтверждённый ШБ либо reboot запрещают раннюю отмену. Нормализация давления не снимает чужие ошибки. Кнопка HMI «Обязательный останов» доступна также во время ещё отменяемого перехода по давлению. |
| Завершённый D-149 | После программного останова остаётся отдельная блокировка. `reset_pressure_stop` допустим только после подтверждённого OFF/новых 000/остановленного ПЧ, при обоих нормальных давлениях; снимает только свои причины. Затем отдельный новый Пуск. Q=0 при OFF не запрещает этот сброс. |
| `RebootRecovery` | Сохраняется **имитируемый снимок в памяти**: прежнее программное состояние, выбранная ветвь, настройки, ошибки/блокировки, обязательные ручные действия и остатки ожиданий. Старые входы, доставка и текущие команды не восстанавливаются как физические факты. При неизвестном/непрочитанном состоянии готовность отсутствует; повторный reboot не делает его достоверным. |
| Инициализация | По D-162 питание ШТ допускается только при новых непротиворечивых входах и достоверно прочитанной неблокированной записи; движения нет. Реализован профиль насосов с новыми 000 обеих ветвей: выдаются OFF, затем нужны новые 000 после команды. ПЧ без запроса охлаждения получает STOP, требуются доставка и новый ответ Работа=0. До восстановления состояния — 5 с непрерывной нормы агрегированного тестового сетевого признака. |
| После RUN/START/STOP | Восстанавливается STOPPING, а не обычная работа. Все ручные подтверждения ШБ аннулируются; для закрытия ШТ нужны новые «ШБ открыт» и отдельное `continue_stop_after_restart`. Устаревшие поколения/контексты отвергаются. При уже закрытом ШТ насос ради останова не включается. |
| Только циркуляция после reboot | При новом OFF/000, исправных ветвях, допустимых давлениях, известных исходных положениях и остальных разрешениях — один цикл восстановления прежней ветви; один 0/0 обрабатывается по новому узкому согласованию. Успех оставляет STOPPING, ПЧ обычного режима не запускается. Самостоятельное давление/ошибка не порождает автоматические повторы. |
| D-257 | Остаток сохраняется без времени заданного простоя и ожидания новых данных. Возобновляется только когда владелец **текущего этапа** вновь запрашивает ту же цель этого затвора; при другой цели старое задание не восстанавливается. Повтор запроса не даёт новых 60 с. Это перенос остатка, не разрешение движения и не универсальное продолжение всех прерванных этапов. |
| HMI/API | Добавлены состояния давления/ожидания после reboot, отдельные кнопки сброса давления и продолжения. В имитаторе входов — явно подписанный образец общих нормальных условий без охлаждения. HTTP `restart` может моделировать длительность простоя и непрочитанное состояние; аппаратные адреса/права не добавлены. |

Различие для интерфейсов: запись `LOW_PRESSURE` в общем списке причин появляется сразу как основание отключения; отдельный `pressure.lowAlarm` означает завершённую выдержку сигнализации 3 с. Существующий общий `alarm/errors` обозначает наличие причин, не назначает физический звуковой выход или новые регистры.

## Что не считать подтверждённым

- **Настоящей энергонезависимости нет.** Нет записи файла/БД, атомарного журнала, защиты от повреждения или реального отключения питания. Снимок теряется при завершении процесса Node.js; новый экземпляр модели его не получает. Параметр простоя — только воздействие испытателя. Физическое поведение выходов при сбросе/выключении WB не моделируется.
- WB 8.5, реальный I/O, физическая фильтрация AI, электросхема, Modbus/доставка, безопасное время без циркуляции и независимость служб в разных процессах не проверены. Агрегированная «норма сети» — существующая предпосылка модели, не реализованный монитор Новатек/WB.
- Восстановление при 111/частичных/неизвестных фазах после загрузки не назначает новую начальную команду насосам: остаются UNKNOWN и понятная причина ожидания. Профиль с требуемым охлаждением также ждёт своей реализации.
- Начальное UNKNOWN/1/1 насосных затворов, оба 0/0 и сохранённые запрещающие неисправности не получают автоматический обход. Гидравлическая неудача первой ветви после reboot, если ещё есть потенциальный резерв, остаётся явной границей смены в STOPPING. При двух установленных отказах действует существующая групповая авария.
- D-257 реализован как сохранение/возобновление актуальной цели, не как полное автоматическое восстановление всех технологических эпизодов. Реальный формат NV и восстановление при повреждённой записи требуют отдельной реализации/проверки.
- Прочие контексты D-177, сочетания аварий сети/температуры/ПЧ и другие ранее обозначенные границы не объявлены закрытыми. Новое согласование одного 0/0 их не заменяет.
