## Согласованное уточнение D-177

Пользователю был задан отдельный вопрос: после ручного подтверждения закрытия неисправного затвора и продолжения другой ветви без новой команды движения пришли новые достоверные концевики **Открыт=1/Закрыт=0**. Снять ручное подтверждение и выполнить обязательный останов через **подтверждение ШБ → закрытие ШТ**, сохранив разрешённую циркуляцию до закрытия ШТ? Ответ пользователя — **«да»** в этой сессии.

Реализован именно этот случай: ручная отметка CLOSED снимается, фиксируется связанная с затвором причина, начинается необратимый останов; исправная ветвь по этому событию непосредственно не выключается. Возврат концевика не отменяет принятый останов. Электрические запреты привода и самостоятельные защиты сохраняются. Известный неисправный концевик, существовавший уже при ручном подтверждении, не считается новым свидетельством; ожидаемые UNKNOWN/0/0 сами отметку не отменяют. В модели «новое» означает новое отличающееся достоверное положение после исходного/ожидаемого состояния; физическая привязка достоверности к WB не проверена.

Обратный случай против ручного OPEN, противоречие в остановленном ТО и остальные контексты **этим ответом не утверждены**. В таких случаях сохранена явная пауза расчёта. Новые D-ID не назначены, уточнение относится к D-177.

## Реализованный охват

| Сценарий | Поведение и границы |
| --- | --- |
| Специальное восстановление D-111/D-112/D-171 | Отдельный `PumpRecovery`: закрытие → выбор допустимой ветви → ON → прежняя 1 с → OPEN → прежние 5 с и пусковая гидравлическая матрица. Не закрывшаяся за 45 с ветвь остаётся OFF, её привод блокируется; доступная другая ветвь с реальным CLOSED допускается к включению. От запроса ручного закрытия — единственные 60 с. Продолжение требует подтверждения циркуляции и закрытия неисправной ветви; ошибка сохраняется. Позднее подтверждение не отменяет останов, таймер не объявляет исправную ветвь неисправной. Обе стороны проверены. |
| Граница входа в D-112 | В HMI/API имеется **тестовая исходная точка**, задающая уже полученный отдельный допуск к восстановлению, открытый ШТ, работающий ПЧ и закрытый ШБ. Она сбрасывает тестовый мир, как прежняя исходная точка; не является командой обхода защиты/пуска. Полная ранняя отмена защиты давления D-149 ещё не реализована. Обычный старт D-139 по-прежнему требует закрытия обоих затворов и не переходит в D-112 автоматически. |
| Гидравлика восстановления | Та же матрица подготовки D-031/D-032 и текущие Qmin/ΔPmin. Неизвестный Q не считается нулём и при включённом контроле не получает рабочего fallback. Низкая циркуляция новой ветви — её отдельный диагноз; две диагностированные ошибки дают D-117/D-118. Самостоятельная защита давления прерывает восстановление и не создаёт повторного ON при нормализации. |
| Полный останов при заблокированном приводе | D-175: дистанционные направления STOP, запрос ручного CLOSED перед OFF работающего насоса; затем отдельный запрос ручного OPEN для положения останова. Переход к OPEN снимает ручное CLOSED. Для этого ручного задания новый таймаут не назначен: 45 с без выданного CLOSE не отсчитываются. Ранее принятые причины/истёкшие сроки сохраняются. Завершение программного останова по прежнему правилу отдельно от физических подтверждений. |
| Обратный переход | При отказе новой ветви по электрической диагностике, неожиданном закрытии/диагнозе затвора либо низкой гидравлике возвращается доступная прежняя ветвь, **уже OFF/000/CLOSED**, по действующей последовательности смены. Обратный ход также требует проверки циркуляции. Прежняя ветвь ещё ON/не закрыта/недоступна — явная граница, без придуманного алгоритма. |
| Восстановление групповой аварии D-116 | После подтверждённого останова инженер может проверять насосы/затворы при сохранённой групповой фиксации. Требуются проверки обоих механизмов обеих ветвей и отдельные возвраты, завершение ручных обязанностей, выход из инженерного режима, отдельный `reset_pump_group`, затем отдельный новый Пуск. Q=0 при OFF не мешает сбросу; посторонние причины не снимаются. Новый индивидуальный отказ аннулирует соответствующие разрешения. После моделируемого reboot прежний сеанс не даёт нового разрешения. |
| Объединённая ветвь D-251 | По отдельной команде инженера для одной ветви: изоляция противоположной → подготовка собственного OPEN → реальный CLOSE → ON → 1 с → OPEN → 5 с → обязательные Q и ΔP независимо от флага → CLOSE при ON → OFF → новые 000 → OPEN. Нет автоматического старта второй ветви. Результаты насоса и затвора раздельные, их возврат отдельными командами. Самостоятельный тест насоса D-190 сохранён. |
| Неудача объединённого теста D-252 | 45 с заключительного закрытия: немедленно OFF и STOP обоих направлений; подтверждение 000 всё ещё обязательно. Ошибка своего затвора, блокировка ветви, без автоповтора/реверса/пуска второго насоса. Электрическая и гидравлическая оценки насоса сохраняются, объединённый результат неуспешен. После подтверждённого OFF отдельное отключение автомата и ручное открытие. Нижний кран также требует возврата, если использован. Промежуточные успешные оценки не дают разрешения возврата неуспешной ветви. |
| Отмена/защиты | В объединённой проверке отмена, потеря HMI, давление, утрата изоляции и электрические причины прекращают проверочные запросы; ожидание заключительного закрытия не добавляется. При давлении разрешённое защитное OPEN сохраняет приоритет. Проверочный ON/напряжение и OFF/новые 000 остаются разными доказательствами. |

Архитектура не изменена: модули формируют запросы, только `Protection` выдаёт виртуальные выходы. Нет аппаратных адаптеров, регистров/адресов Modbus, новых физических входов или новых обязанностей ARANGA/котельной. Все службы всё ещё моделируются внутри одного Node.js-процесса.

1. Полная процедура допуска/раннего возобновления D-149 и согласованное восстановление этапов после reboot D-257, файловая энергонезависимость и аварийное завершение процесса.

3. Общий порядок всех инженерных механизмов остаётся открытым. Реализована объединённая **насосная ветвь**, а не общий цикл всей установки. Следом — матрица сочетаний отказов и независимые тесты других механизмов по уже утверждённым решениям.
