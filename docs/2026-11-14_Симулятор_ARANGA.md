## Реализованные утверждённые правила

| Область | Реализация и источник |
| --- | --- |
| Пуск ARANGA | Однократный 0→1; после загрузки/потери связи сначала 0; отказанный Пуск не запоминается. [D-298](2026-11-13_Итоги_сессии.md#d-298). |
| Стоп ARANGA | По уровню, выше Пуска, повтор не сбрасывает процедуру; до снятия принятого Стоп=1 новый пуск запрещён. [D-299](2026-11-13_Итоги_сессии.md#d-299). Это явная принятая команда, а не зависимость ручного режима от наличия связи. |
| Выбор режима | При остановленном ТО; ручной → ARANGA в работе запрещён; на запуске режим фиксирован; ARANGA → ручной в работе берёт итоговое задание, не обратную связь. [D-267](2026-11-10_Итоги_сессии.md#d-267), [D-297](2026-11-11_Итоги_сессии.md#d-297), [D-329](2026-11-14_Итоги_сессии.md#d-329). |
| Подготовка | Общая последовательность механизмов; в сквозном режиме Fmin до первой записи **после** перехода В работе. Старый регистр/ранняя запись не заменяют его, нового таймера первой частоты нет. [D-295](2026-11-11_Итоги_сессии.md#d-295). |
| Обычная работа | Ручной независим от наличия ARANGA; сквозной применяет внешнее задание через LIMIT/резонанс. [D-328](2026-11-14_Итоги_сессии.md#d-328), [D-294](2026-11-11_Итоги_сессии.md#d-294). |
| Потеря ARANGA в работе | Через 5 с удерживается последний итог; местная корректировка при доступной HMI; режим сквозной сохраняется. Нет перехода на 38 Гц/останова только по этой причине. [D-330](2026-11-14_Итоги_сессии.md#d-330). |
| Восстановление в работе | Чтение восстанавливает индикацию связи, но не снимает удержание; первая новая принятая запись частоты возвращает управление. То же числовое значение допустимо. [D-331](2026-11-14_Итоги_сессии.md#d-331). |

При утрате HMI применяется 25 Гц; при обеих причинах этот приоритет сохраняется независимо от порядка/восстановления. [D-259/D-260](2026-11-10_Итоги_сессии.md#d-259), [D-273](2026-11-10_Итоги_сессии.md#d-273), [D-287](2026-11-11_Итоги_сессии.md#d-287). |
| Командный останов | До закрытия ШТ частота охлаждения 25 Гц; новые сетевые частоты/Пуск не вытесняют процедуру. [D-262/D-263](2026-11-10_Итоги_сессии.md#d-262). |
| Обратная информация | Состояние/режим, готовность и причины, ошибки, итог/фактическая частота с достоверностью, LIMIT/резонанс. [D-301/D-303](2026-11-13_Итоги_сессии.md#d-301). Выборка пока не содержит все данные общего контракта. |

Защитная часть по-прежнему единственный отправитель итоговых команд. Добавлен предцикловой контроль связи: истёкший таймаут запуска нельзя скрыть переходом В работе или поздней записью на той же отметке времени. Это порядок обработки утверждённых условий, не новый таймаут.

## Техническая реализация и интерфейс испытателя

- `simulator/src/aranga.mjs`: операции `read`, `controls`, `frequency`, `failed`; контроль успешного обмена, фронта Пуска, принятого Стопа, удержания и источника частоты. Никаких Modbus-адресов, реальных сетевых соединений или программирования ARANGA.
- `controls` передаёт оба bool-уровня вместе, чтобы проверять одновременный Пуск/Стоп без порядка HTTP-вызовов. Форма API — технический формат симулятора, не карта регистров.
- Счётчик частотных записей различает события с одинаковым временем/числом; это не дополнительный watchdog и не требование нового регистра печи.
- Последняя попытка и успешная операция разделены. Для частоты отдельно хранятся последнее хорошее число, качество последней попытки, время попытки и последней достоверной записи. Некорректный payload условного API отклоняется, последнее задание не заменяется нулём. Ответы/диагностика реального Modbus-драйвера ещё не назначены.
- Генератор ARANGA повторяет **только чтения**, целевой интервал 500 мс модельного времени. Команды и частота требуют отдельных действий испытателя. Обмен HMI/других устройств не сбрасывает таймер ARANGA.
- Веб-HMI показывает режим, источник частоты, удержание, связь, дистанционную готовность и причины. Есть отдельные кнопки чтения/неуспешной операции, запись двух уровней и частоты. Местные кнопки ±1 Гц — D-270.
- При моделируемом перезапуске известные режим/ручное задание сохраняются только в памяти текущего процесса. Основное состояние вновь неизвестно, сетевые уровни/частота не воспроизводятся. Это не реализация NV после выключения питания.

## Проверки

Node.js 24.20.0 / Windows: **46/46 автоматических тестов прошли**. Из них 24 прежних сценарных теста, 20 новых тестов ARANGA и 2 HTTP-теста. Проверяются граница 5 с, первая запись после запуска, одинаковое новое значение, запреты/приоритеты Пуска и Стопа, оба порядка совместной потери, поздний ответ на границе таймаута, отсутствие самопуска выключенного дымососа, команды после перезапуска, качество частоты, LIMIT/резонанс и полный цикл через HTTP. Отдельно проверена явная остановка расчёта при открытом сочетании старого раннего регистра и восстановления только чтения при прерванном запуске.

Веб-HMI **не проверена визуально в браузере**; прежнее ограничение запуска браузера не обходилось, новых зависимостей/прав/настроек безопасности не добавлено. HTTP-тест не является тестом рендера или браузерных событий.

## Ограничения и вопросы

1. Проверены только нормальные температуры/сеть/отсутствие охлаждения и ветвь 1. Общая физическая схема, защиты, резервирование, ПИД ШОД, инженерные проверки, учёт/NV и отдельные службы по-прежнему не завершены.
2. Переключение режима **во время состояния Останов** не включено в интерфейс v0.2. Это ограничение охвата, не новое решение о технологическом запрете. Подробный порядок такого переключения и влияния на частоту D-260 нужно сверить до расширения; уже принятый останов отменять нельзя.
3. В v0.2 проверен возврат частоты D-260 по новой достоверной записи. Сочетание восстановления только чтения после обрыва при наличии раннего регистра, записанного ещё до завершения запуска, **вызывает паузу модели с пояснением**; дальнейшая выдача не рассчитывается. Не объявляется согласованным ни применение старой частоты, ни новая реакция удержания. Перед расширением этой области следует уточнить применение D-294 к данному сочетанию. На рабочую реакцию D-331 это не переносится: там новая запись прямо обязательна.
4. Реальные регистры/клиенты/драйверы, производственная авторизация и несколько HMI не назначены. Синтетическая доступность HMI не означает фактический контроль открытого браузера.
5. Реакции на отказ служб вне обычной работы и выходы при остановке всей ОС остаются открытыми по O14-01/O14-02. Модель в одном процессе не даёт аппаратных гарантий.

Следующий независимый этап — насосная ветвь 2 и согласованная процедура резервирования с фазными выдержками/качеством входов; сначала сверить D-117 и поздние уточнения, не считать общую недостоверность отказом второй ветви. Перед этим желательно визуально пройти HMI. Открытые вопросы не утверждены автоматически, дальнейшей публикации не поручено.
