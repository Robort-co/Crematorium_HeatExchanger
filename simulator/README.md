# Симулятор теплообменника — первая версия 0.1

Только имитированные сигналы. Реальных драйверов, MQTT, Modbus, GPIO и подключений к оборудованию нет. Не программа для загрузки на действующий шкаф. [Программный контракт](../docs/2026-11-14_Контракт_сигналов_симулятора_WB.md) принят как черновая основа, физическая схема не проверена.

## Запуск

Нужен Node.js 22 или новее. В этой среде проверяется Node.js 24.20.0 на Windows; на WB8.5 код не запускался. Внешних npm-пакетов нет, `npm install` не требуется.

```powershell
cd 'P:\Projects\Теплообменник\simulator'
node server.mjs
```

Открыть <http://127.0.0.1:8765>. Сервер слушает только loopback. Остановка — Ctrl+C в запустившем терминале. Для другого локального порта можно задать `HX_SIM_PORT`; это не настройка оборудования. Сервер не пишет модель на диск.

```powershell
node --test test/*.test.mjs
```

Тесты сценария детерминированы; реального ожидания 45/67,5 с нет. HTTP-тест создаёт локальный сервер на временном порту. Если среда блокирует loopback, это ограничение окружения, а не подтверждение отказа сценарного ядра.

## Структура и переносимость

| Файл | Ответственность |
| --- | --- |
| `src/signals.mjs` | Типы входов, качество, времена последнего ответа/достоверного значения, часы модели, независимые генераторы повторных образцов |
| `src/io.mjs` | Виртуальная доставка по ID команды; не изменяет обратную связь |
| `src/main-program.mjs` | Основной ручной запуск и рабочие запросы; не имеет права итоговой выдачи |
| `src/protection.mjs` | Единственная итоговая выдача D-323, реализованные защитные приоритеты, независимая процедура обязательного останова |
| `src/supervision.mjs` | Модель завершённых циклов надзора, отдельная от основной программы |
| `src/frequency.mjs` | LIMIT и согласованный обход одной зоны резонанса с гистерезисом |
| `src/simulation.mjs` | Оркестрация, фикстура, входы испытателя, журнал, запросы HMI; не физический драйвер |
| `server.mjs` | HTTP только на localhost, проверка поколения модели, фиксированный список ресурсов и команд |
| `web/` | Простая HMI без библиотек: управление, подтверждения, входы/выходы, журнал |
| `test/` | Автоматические сценарные и HTTP-проверки |

Язык — JavaScript ES-модули, сервер/тесты Node.js, HMI HTML/CSS/JavaScript. Ядро не использует DOM, реальные сетевые устройства и системные часы. Время передаётся через `ManualClock`.

**Логические модули сейчас исполняются в одном процессе.** Это не доказательство независимости служб при зависании Node.js. На WB потребуются отдельные процессы, межпроцессный обмен, системный надзор, реальные адаптеры и NV-хранилище. Выбор Node.js как исполняемой среды целевого шкафа пока не утверждает его установку/версию. Производитель описывает [приложения Node.js](https://wiki.wirenboard.com/wiki/Nodejs); встроенный [wb-rules использует ECMAScript 5](https://github.com/wirenboard/wb-rules), поэтому эти ES-модули нельзя просто скопировать в `/etc/wb-rules`. Оба источника просмотрены 14.11.2026. Версия ПО конкретного WB8.5 и запуск на нём не проверены.

## Как пройти реализованный сценарий

1. При открытии состояние **неизвестно**, Пуск запрещён. Нажать «Загрузить тестовую точку Остановлен». Это явное создание искусственного мира, не операторская процедура подтверждения реального останова.
2. Нажать «Пуск ТО», доставить команды. Отдельно имитировать открытие ШТ.
3. Доставить новые команды; отдельно задать оба закрытых насосных затвора и работу ПЧ.
4. Доставить включение насоса; отдельно задать три фазных подтверждения насоса 1. Продвинуть время на 1 с.
5. Доставить открытие затвора; отдельно задать «затвор 1 открыт» и нормальные тестовые Q/P. Продвинуть 5 с.
6. Подтвердить оператором закрытие ШБ. Только теперь ТО «В работе», применяется ручная частота.
7. Нажать «Обязательный останов». Пока ШБ не подтверждён открытым, насос остаётся включённым при действующих разрешениях. Частота — охлаждения.
8. Подтвердить открытие ШБ; доставить команду ШТ и отдельно имитировать его закрытие.
9. Доставить команды; отдельно задать закрытие затвора 1. Насос OFF по концевику либо по 45 с. Выдаются положения останова (оба открыты), процедура завершается без ожидания их достижения.
10. Доставить STOP ПЧ/остальные команды, отдельно задать отсутствие фаз и останов ПЧ. Отдельный индикатор физического останова станет подтверждённым по новым входам. Само состояние программы «Остановлен» не подделывает этих входов.

Фикстура использует **тестовые** P1=1,5 бар, P2=1,5/2 бар, Q=0/8 м³/ч; это не новые проектные уставки. Предполагаются нормальная сеть/температуры, отсутствие охлаждения и заранее настроенная конфигурация/результат проверки резонанса. Непроверенный реальный объект этими предпосылками не описывается.

## Данные, время и комментарии

- Переменные имеют пояснения на русском при объявлении; функции/параметры и ключевые ветви отмечены назначением и ссылками D-xxx. Комментарий не заменяет тест или источник решения.
- Вход `UNKNOWN` не равен false/0. Команда, доставка и физическая обратная связь независимы.
- `updatedAt` меняется при ответе с диагностической ошибкой; `lastGoodAt` при этом сохраняется. Повтор правильного прежнего значения является новым ответом.
- Номер ответа отличает новые данные от прежних даже при одном модельном времени. После START/STOP ПЧ требуется ответ, пришедший после подтверждения записи.
- Время двигается только испытателем. Технический шаг вычисления модели 100 мс не назначает цикл/период опроса реального WB.
- Флажок «повторять» моделирует независимые циклические ответы с прежним показанием; команды механизмам на него не влияют. Отключение позволяет испытывать устаревание. Прямые аналоговые сигналы в v0.1 считаются уже после фильтра, сам фильтр 2 с ещё не реализован.
- Переключатели обмена HMI/ARANGA — синтетические источники прикладных операций. Это не проверка реальных сетевых соединений или закрытия браузера.
- У HMI v0.1 один испытатель, нет производственной авторизации. Проверяются поколение модели, типы и контекст команд; старое окно после перезапуска/фикстуры не может повторить команду.

## Охват и границы

Реализованы: ручной запуск ветви 1 с независимыми концевиками/фазами/статусом ПЧ/Q/ΔP; подтверждение ШБ; ручная частота; обязательный останов; запрет отмены и очереди Пуска; давление ниже порога/потеря обоих давлений; часть диагностики ШТ; раздельные причины отсутствия обратной связи и неподтверждённой цели; HMI при запуске/работе; независимость ручного режима от ARANGA; модель двух таймаутов надзора 2 с для уже работающего ТО.

**Не реализованы полностью:** электрическая диагностика и резервирование насосов; сквозной запуск/управление ARANGA и возврат после записи; полный контроль сети и температур, ПИД ШОД, охлаждение, сбросы/повторы ПЧ, прочие аварийные сочетания; инженерные тесты; наработки/календарь/тепловой учёт; производственный NV и восстановление; отдельные процессы/systemd; реальные адаптеры/права/карты.

Не каждый общий вход чернового контракта уже создан в коде. Есть явные агрегированные тестовые предпосылки вместо не реализованных подсистем. Выход за охват помечается **NOT_IMPLEMENTED / ПАУЗА МОДЕЛИ**; последняя команда остаётся историей выдачи, физическое поведение дальше не предсказывается. Это не новый алгоритм безопасного удержания оборудования. Нового решения об аварийной реакции не вводится.

Перезапуск модели демонстрирует неизвестность и сохранение уже известных ошибок в памяти процесса; он **не является** испытанием восстановления после выключения питания или прерванной NV-записи. Загрузка новой фикстуры сбрасывает весь искусственный мир и не является кнопкой сброса аварий реальной HMI.

Точные результаты проверки и ограничения среды — [итоги разработки](../docs/2026-11-14_Начало_симулятора.md). Реальная схема, подключения и аппаратная защита не проверены. Эта версия не доказывает готовность шкафа или безопасного пуска.
