Давление и восстановление

Немедленное отключение и сигнализация после 3 с различаются. Кнопка перезапуска имитирует сохранение только в памяти Node.js: закрытие процесса теряет снимок. После перезапуска нужны новые входы и отдельные подтверждения; старые DI и команды не доказывают текущее состояние.

Режим и источник задания

Источник частоты: —

Ручной → ARANGA только после завершения останова. ARANGA → ручной в работе переносит текущее выдаваемое задание. Во время запуска режим фиксирован.

Местное управление

Кнопки создают запросы. Принятие не означает исполнение.

В сквозном режиме местная корректировка доступна после диагностированной потери ARANGA до новой записи частоты.

    Положение и фазные входы независимы от команды. Наличие напряжения не доказывает вращение.

    Насосная группа · смена и резерв

    Инженерные права здесь условные, производственной авторизации нет. При OFF измерение Q продолжается. Принятая смена по низкому Q всё равно проверяет расход результата.

    Ручное подтверждение не меняет концевики и не снимает неисправность. Автоматы насоса и привода затвора — разные устройства. 45 + 60 с — таймеры процедуры, не подтверждённое безопасное время работы насоса.

    Отдельные инженерные проверки

    Только имитация. Выключенная печь и квалификация инженера — явные предпосылки испытателя; аппаратное подтверждение и производственные права не реализованы. Тест не запускает ТО. Успех не снимает ошибки автоматически.

    Для проверки затвора после ремонта вручную включают его отдельный автомат при снятых командах. Для насоса также требуется подготовленное питание насоса. После прерывания ремонтной проверки затвора автомат нужно снова отключить.

    Проверка ШТ

    Закрыт → Открыт → Закрыт. При работающем охлаждении до открытия нужны Q, ΔP и местная циркуляция с затвором, открытым не менее 5 с. Потеря требуемой циркуляции прекращает тест и вызывает разрешённое закрытие. После ремонта сначала отдельный возврат питания. Сохранение — только память процесса.

    Проверка ШОД

    ШОД: не подтверждено изменение обратной связи (D-020).

    0 → 50 → 100 → 50 → 0%, допуск ±10 п.п., непрерывные 2 с в пределах 52,5 с каждого этапа. K корректирует только обратную связь. Охлаждение прекращает тест ШОД; недостоверность не считается нулевым положением.

    Проверка дымососа

    Частые повторные пуски охлаждения после потери циркуляции. Дополнительная блокировка не вводится.

    Подтверждение действует только на текущий цикл охлаждения: не изменяет концевики, ошибку, питание ШТ или запрет нового Пуска. Перезагрузка, окончание цикла, выданное движение или новое Открыт=1/Закрыт=0 отменяют его. При остальных разрешениях возможен пуск дымососа. После reboot все входы и доставка STOP подтверждаются заново; ШБ и «Продолжить останов» остаются отдельными действиями.

    Подтверждённый STOP → Fmin → ступени по 5 Гц → Fmax → подтверждённый STOP. Каждая ступень, включая последнюю, требует «Продолжить». Охлаждение не прерывает тест. Отмена и нарушение частоты отдельно запрещают обычный пуск и охлаждение; успешный повтор снимает только запрет обычного пуска.

    Реальное значение внутренней резервной частоты не назначено. Его проверка здесь — явное допущение испытателя; записи параметров в ПЧ нет. Изменение границ требует нового полного теста.

    Отдельный возврат разрешения охлаждения

    При сохранённом запросе после подтверждения возможен автоматический пуск охлаждения. Причина вибрации должна быть выяснена и устранена.

    Общий инженерный цикл

    Ветвь 1 → ветвь 2 → ШТ → ШОД → дымосос. Каждый следующий механизм запускается отдельно после повторной проверки допуска. Пропуск не означает успешную проверку.

    Тест насоса: противоположная ветвь изолирована → свой затвор закрыт → насос → открытие → через 5 с проверка Q и ΔP независимо от флага → OFF с новым подтверждением 000. Отдельный тест затвора: открыт → закрыт → открыт. Все входы задаются испытателем отдельно.

    Сброс аварий расхода требует достоверных Q и обоих давлений. Нулевой расход при OFF допустим; требование следующего полного пуска по Q и ΔP сохраняется.

    ИМИТАТОР ARANGA · БЕЗ MODBUS

    Прикладные операции печи

    Связи нет · —

    Для первого Пуска запишите 0/0, затем 1/0. Уровень Стоп=1 имеет приоритет. Генератор обмена выше повторяет только успешные чтения каждые 500 мс модельного времени. Для проверки потери отключите его и продвиньте время на 5 с. Пустое поле частоты моделирует отсутствие значения.

    ДЕЙСТВИЯ ИСПЫТАТЕЛЯ

    Имитатор входов и времени

    Исходная точка — искусственные данные о холодном остановленном ТО и настроенной системе. Не подтверждение состояния реальной установки. Время идёт только по кнопкам; включённые генераторы повторяют показания независимо от команд.

    Пошаговый пример
    1. Загрузить исходную точку и нажать «Пуск ТО».
    2. Доставить команды, отдельно имитировать «ШТ открыт».
    3. Доставить новые команды, отдельно имитировать «оба затвора закрыты» и «ПЧ работает».
    4. Доставить команду насоса, отдельно имитировать его напряжение. Продвинуть 1 с.
    5. Доставить открытие затвора, отдельно задать «затвор 1 открыт» и нормальный расход. Продвинуть 5 с.
    6. Подтвердить закрытие ШБ — состояние «В работе».
    7. Нажать «Обязательный останов», подтвердить открытие ШБ. Доставить закрытие ШТ и отдельно имитировать его закрытие.
    8. Доставить команды, отдельно имитировать «затвор 1 закрыт». После выключения насоса доставить новые команды.
    9. Отдельно задать отсутствие фаз и останов ПЧ. Открытые затворы останова можно имитировать отдельно; их достижения программа для завершения не ждёт.

    Исходные точки охлаждения

    Входные сигналы

    GOOD — достоверно, BAD — диагностическая ошибка, UNKNOWN — данных нет. «Актуален» и «повторять ответы» задаются отдельно. Прямые аналоговые входы здесь уже после фильтра; физический фильтр 2 с пока не моделируется.

    Журнал событий

    Моделируются логические модули в одном процессе Node.js. Изоляция служб, systemd, реальные драйверы, NV, полный набор защит и инженерных тестов ещё не реализованы. Результат не подтверждает готовность шкафа или безопасный пуск.

    Температурные источники

    Отдельная исходная точка: ТО остановлен, ШТ закрыт, температура ещё не получена. GOOD означает нормализованное измерение в проверенном диапазоне; реальные AI и TUF не подключены. Прочие температурные разрешения остаются тестовой предпосылкой. Сохранение — только память процесса.

    Расхождение двух подач: предупреждение без запрета Пуска и без выбора неисправного датчика.

    Измерения задаются в таблице входов: temperature.fan / supply / backup / return. В этом профиле cooling.required вычисляется автоматически. Для проверки водяных защит отдельно загрузите водяной профиль ниже; температурная исходная точка сама его не включает.

    Водяные защиты и сроки TUF

    Исходные 40/60/60/50 °C — испытательные показания, не измерения объекта. Перегрев/потеря подачи запрещают новый Пуск; работающий ТО продолжает работу. Теплоотвод — только логический запрос, без подтверждения вентилятора или команды реальной котельной. Восстановление водяного профиля после reboot пока явно приостанавливает расчёт.
